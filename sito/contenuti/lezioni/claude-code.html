TPSI · Strumenti di sviluppo con l'intelligenza artificiale

Claude Code

Un assistente AI che non si limita a rispondere: legge il progetto, modifica i file ed esegue i comandi. Come funziona e come usarlo con giudizio.

Aprire chiedendo: "chi ha già usato un chatbot per farsi aiutare con il codice? Cosa dovevate fare voi a mano dopo?". Obiettivo: capire la differenza tra chatbot e agente, saper scrivere una buona richiesta, saper controllare il codice generato.

Il punto di partenza

Da chi risponde a chi agisce

Chatbot

  • Vede solo ciò che incolli nella chat.
  • Ti suggerisce il codice.
  • Copi, incolli, compili e provi tu.

Agente

  • Esplora da solo i file del progetto.
  • Modifica direttamente il codice.
  • Esegue compilazione e test, legge gli errori e corregge.

Un agente è un modello di linguaggio che può usare strumenti e decidere da solo il passo successivo.

Sottolineare che il modello sottostante può essere lo stesso: cambia ciò che gli permettiamo di fare. Più potere significa anche più attenzione.

Che cos'è

Claude Code in breve

  • Strumento di programmazione agentico sviluppato da Anthropic.
  • Lavora dentro la cartella del tuo progetto.
  • Legge e scrive file, esegue comandi da terminale, usa git.
  • Si comanda in linguaggio naturale, anche in italiano.
  • Richiede un account Claude o una chiave API.

Come ragiona

Il ciclo dell'agente

1

Capisce

Legge la richiesta e i file utili del progetto.

2

Pianifica

Decide quali file cambiare e in che ordine.

3

Agisce

Modifica il codice ed esegue i comandi.

4

Verifica

Compila, lancia i test, legge gli errori.

Se la verifica fallisce, il ciclo ricomincia: è lo stesso modo di lavorare di un buon programmatore.
Chiedere: "che cosa fate voi quando il compilatore vi dà un errore?". Leggere, capire, correggere, riprovare: l'agente automatizza questo giro. Senza test, il passo 4 è debole: ecco perché i test contano ancora di più.

Un esempio

Una richiesta, tanti passi

$ claude
> Il server della chat si blocca quando un client si disconnette.
  Trova la causa, correggila e verifica con un test.

● Leggo ServerChat.java e GestoreClient.java
● Causa: l'eccezione di readLine() non viene gestita
● Modifico GestoreClient.java   ← chiede il permesso
● Eseguo i test: 3 superati, 0 falliti

Esempio illustrativo: l'aspetto reale dello schermo cambia con la versione del programma.

Collegare al programma di TPSI: socket e server multi-thread. Far notare che la richiesta contiene il problema, l'obiettivo e il modo di verificarlo.

Chi decide

Tu resti al comando

?

Permessi

Prima di modificare file o eseguire comandi chiede conferma. Puoi accettare, rifiutare o correggere la rotta.

≡

Modalità piano

Con Maiusc + Tab si passa alla modalità piano: l'agente analizza e propone, senza toccare nulla.

■

Interruzione

Con Esc lo fermi in qualsiasi momento e gli dai nuove indicazioni.

Buona abitudine: chiedi prima il piano, leggilo, e solo dopo lascia che scriva il codice.
Le modalità di permesso si scorrono con Maiusc+Tab (normale, accetta modifiche, piano). Insistere sul fatto che "accetta tutto" senza leggere è il modo più rapido per perdere il controllo del proprio progetto.

Al computer · 15 minuti

Scrivi una buona richiesta

Questa richiesta è troppo vaga: "sistema il login del sito".

Apri un editor di testo e riscrivila in un file richiesta.txt con quattro parti:

  1. Contesto: che progetto è, quali file.
  2. Problema: cosa succede ora.
  3. Obiettivo: cosa deve succedere.
  4. Verifica: come capire che funziona.

Suggerimento

Immagina di scrivere a un collega bravo che non ha mai visto il tuo progetto.

Controllo: scambia il file con il compagno. Riesce a capire cosa fare senza farti domande?
Esempio di soluzione: "Progetto: sito PHP della biblioteca, file login.php e db.php. Problema: con password corretta compare 'credenziali errate'. Obiettivo: login riuscito con utente e password validi, errore con password sbagliata. Verifica: provare entrambi i casi con l'utente di prova e mostrare l'esito." Discutere 2-3 richieste alla lavagna.

La memoria del progetto

Il file CLAUDE.md

Un file di testo nella cartella del progetto che l'agente legge all'inizio di ogni sessione.

  • Come si compila e come si lanciano i test.
  • Regole di stile del codice.
  • Cose da non fare.

Il comando /init ne crea una prima versione analizzando il progetto.

# Chat TCP in Java

## Comandi
- Compila: javac -d out src/*.java
- Server:  java -cp out ServerChat

## Regole
- Nomi di classi e metodi in italiano
- Porta di default: 5000
- Non modificare Protocollo.java
Paragone: è il foglio che lasceresti a un supplente. Il file usa il formato Markdown: # per i titoli, - per gli elenchi.

Al computer · 20 minuti

Il CLAUDE.md del tuo progetto

Scegli un progetto che hai già sviluppato in TPSI (ad esempio il client/server con i socket). Nella sua cartella crea il file CLAUDE.md con:

  • una riga che descrive il progetto;
  • i comandi esatti per compilare ed eseguire;
  • almeno tre regole del progetto;
  • almeno una cosa da non fare.

Prova sul campo

Apri un terminale nuovo e copia i tuoi comandi uno a uno: devono funzionare così come sono scritti.

Controllo: un compagno, leggendo solo il tuo file, riesce a compilare e avviare il progetto.
Il file è utile anche senza AI: è documentazione per chi riprende il progetto. Raccogliere i file su Classroom; valutare chiarezza e correttezza dei comandi.

Oltre le basi

Si può estendere

MCP

Strumenti esterni

Il Model Context Protocol è uno standard aperto per collegare l'agente a database, GitHub, documentazione e altri servizi.

Sub

Subagenti

Agenti specializzati a cui delegare un compito, ad esempio cercare nel codice o fare una revisione.

Hook

Automatismi

Comandi che partono da soli in certi momenti, ad esempio formattare il codice dopo ogni modifica.

Idea chiave: l'agente diventa più utile quanto più contesto e strumenti gli dai.

Solo panoramica. Collegamento con i sistemi distribuiti: MCP funziona con un modello client-server, l'agente è il client e ogni servizio collegato espone strumenti come server.

Al computer · 15 minuti

Revisiona il codice generato

Un agente ha scritto questo metodo per calcolare la media dei voti. Copialo in un progetto Java e provalo con {6, 7, 8}.

public static double media(int[] voti) {
    int somma = 0;
    for (int i = 1; i < voti.length; i++) {
        somma += voti[i];
    }
    return somma / voti.length;
}

Consegna

Trova gli errori, correggili e scrivi in un commento perché erano sbagliati.

Controllo: ci sono almeno due errori. Corretto, il metodo restituisce 7.0; com'è ora restituisce 5.0.
Errori: 1) il ciclo parte da 1 e salta il primo voto; 2) somma / voti.length è una divisione intera, serve (double) somma / voti.length. Bonus: con array vuoto la divisione intera lancia ArithmeticException; gestire il caso. Con gli errori: somma = 15, 15 / 3 = 5, restituito come 5.0.

Usarlo bene

Buone pratiche e rischi

Da fare

  • Usa git e fai commit spesso: puoi sempre tornare indietro.
  • Chiedi il piano prima del codice.
  • Leggi ogni modifica e lancia i test.

Da evitare

  • Inserire password, chiavi o dati personali.
  • Accettare comandi che non capisci.
  • Consegnare codice che non sai spiegare.
Collegare alla sicurezza: i file .env con le chiavi non vanno mai condivisi. Ricordare il regolamento della scuola sull'uso dell'AI nelle verifiche.
