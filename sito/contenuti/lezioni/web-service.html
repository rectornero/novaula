I web service

Programmi che parlano con altri programmi attraverso il Web, in qualunque linguaggio e su qualunque sistema. Il linguaggio comune: XML o JSON.

Obiettivi: definire un web service, spiegare l'interoperabilità, leggere e scrivere documenti XML e JSON corretti, conoscere XSD e JSON Schema, sapere come si descrive e si trova un servizio (WSDL, OpenAPI, UDDI), usare un web service pubblico da curl e da Java. Per cominciare

Ordini una pizza con un'app e paghi con la carta. Quante aziende diverse si parlano?

  1. Una sola: quella dell'app
  2. Due o tre
  3. Da quattro a sei
  4. Più di sei
Ricostruire insieme alla lavagna: l'app di consegne, la pizzeria (o il suo gestionale), il servizio di mappe, il fornitore dei pagamenti, il circuito della carta, la banca del cliente, la banca della pizzeria, il servizio di notifiche push del sistema operativo, spesso un servizio di SMS. Facilmente più di sei. Nessuna di queste aziende usa lo stesso linguaggio di programmazione o lo stesso database: comunicano con web service. È il problema dell'interoperabilità.

Definizione

Che cos'è un web service

Un sistema software progettato per l'interazione tra macchine in rete, con un'interfaccia descritta in un formato leggibile da un programma.

Dalla definizione del W3C, Web Services Architecture, 2004 (riassunta)

  • Usa i protocolli del Web, soprattutto HTTP.
  • I dati viaggiano come testo strutturato: XML o JSON.
  • Chi lo usa conosce solo l'interfaccia, non il linguaggio di chi lo offre.

Pagina web o web service?

Pagina web: HTML per occhi umani, con colori e impaginazione.

Web service: dati puri per un programma, che li elabora e li mostra a modo suo.

La stessa previsione del tempo: una pagina per te, un JSON per l'app.

La definizione originale del W3C (Web Services Architecture, W3C Working Group Note, febbraio 2004) cita esplicitamente WSDL e SOAP: "A Web service is a software system designed to support interoperable machine-to-machine interaction over a network. It has an interface described in a machine-processable format (specifically WSDL)...". Oggi il termine si usa in senso più ampio e comprende anche i servizi REST con JSON. Rispetto a RMI della lezione 2: un web service non lega client e server allo stesso linguaggio e usa porte e protocolli che le reti aziendali lasciano passare (80 e 443).

Menti che ci hanno preceduto

Standard, al plurale

SOAP

Protocollo standard del W3C: messaggi XML in una busta, contratto WSDL, molte estensioni per sicurezza e affidabilità. Lezioni 6 e 7.

REST

Uno stile architetturale, non un protocollo: risorse con un URI, metodi HTTP, quasi sempre JSON. Lezioni dalla 8 in poi.

Originale: "The nice thing about standards is that you have so many to choose from." Traduzione nostra. La frase compare nella prima edizione di Computer Networks (1981) di Tanenbaum, lo stesso autore del manuale sui sistemi distribuiti citato nella lezione 1. Linus Torvalds scrisse Linux partendo da MINIX. Ironia vera: per i web service esistono SOAP, REST, gRPC, GraphQL, JSON-RPC, e ognuno ha i suoi formati. Oggi le API pubbliche sono quasi tutte REST con JSON, ma SOAP resiste in banche, assicurazioni e pubblica amministrazione.

Due formati, lo stesso dato

XML e JSON a confronto

<?xml version="1.0" encoding="UTF-8"?>
<studente id="7">
  <nome>Ada Lovelace</nome>
  <classe>5G</classe>
  <voti>
    <voto materia="TPSI">9</voto>
    <voto materia="Sistemi">8.5</voto>
  </voti>
  <rappresentante>true</rappresentante>
</studente>
{
  "id": 7,
  "nome": "Ada Lovelace",
  "classe": "5G",
  "voti": [
    { "materia": "TPSI", "voto": 9 },
    { "materia": "Sistemi", "voto": 8.5 }
  ],
  "rappresentante": true
}

XML: elementi con tag di apertura e chiusura, attributi, un solo elemento radice. Tutto è testo: il tipo lo dice uno schema.

JSON: oggetti {}, array [], stringhe, numeri, true, false, null. Più corto, ed è JavaScript.

Contare i caratteri: la versione XML è circa una volta e mezza quella JSON, per via dei tag di chiusura. In XML "9" e "true" sono testo: è lo schema XSD a dire che sono un intero e un booleano. In JSON il tipo è scritto nel dato, ma i tipi sono pochi: non esistono date, interi e decimali distinti, caratteri. JSON (JavaScript Object Notation) è stato reso popolare da Douglas Crockford all'inizio degli anni 2000; oggi è definito dalla RFC 8259 (2017) e dallo standard ECMA-404. XML è una raccomandazione W3C del 1998, figlio di SGML come l'HTML.

Le regole

Ben formato, valido, con il suo schema

XML ben formato

  • Un solo elemento radice
  • Ogni tag aperto viene chiuso, nell'ordine giusto
  • Maiuscole e minuscole contano: <Nome> non chiude <nome>
  • Valori degli attributi tra virgolette
  • & e < nel testo si scrivono &amp; e &lt;

JSON corretto

  • Chiavi e stringhe tra virgolette doppie
  • Nessuna virgola dopo l'ultimo elemento
  • Niente commenti
  • Numeri senza zeri iniziali: 17, non 017
  • true, false, null in minuscolo
Valido significa di più: il documento rispetta uno schema che dice quali elementi, in che ordine e di che tipo. Per XML si usa XSD, per JSON JSON Schema.
Un documento XML può essere ben formato ma non valido (per esempio un voto con il testo "nove" quando lo schema vuole un decimale). Un parser rifiuta sempre un documento mal formato; la validazione rispetto a uno schema è invece un passo in più, facoltativo. Il WSDL della lezione 6 contiene proprio uno schema XSD dei messaggi. JSON Schema è usato anche per descrivere gli strumenti dei modelli AI: lo vedremo nel box Oggi.

Puzzle

Trova l'errore: abbina ogni frammento al suo problema

<voto>9</Voto>
Maiuscole diverse tra apertura e chiusura
<a><b></a></b>
Tag chiusi nell'ordine sbagliato
<voto valore=9/>
Valore dell'attributo senza virgolette
{'nome': 'Ada'}
Virgolette singole, JSON vuole le doppie
[1, 2, 3,]
Virgola dopo l'ultimo elemento
Tutti errori che i parser segnalano subito. Il terzo e il quarto sono quelli che fa chi viene dall'HTML (che tollera attributi senza virgolette) o da Python (che accetta le virgolette singole nei dizionari). La virgola finale è permessa in JavaScript e in Python ma non in JSON. Chiedere: come si correggono? (<voto>9</voto>, <a><b></b></a>, <voto valore="9"/>, {"nome": "Ada"}, [1, 2, 3].)

Quiz a trabocchetto

Devi mandare in JSON la data di una verifica. Come la scrivi?

  1. Con il tipo date di JSON
  2. Come stringa ISO 8601, per esempio "2026-10-19"
  3. Come numero, per esempio 19102026
  4. Non si può: JSON non contiene date

JSON non ha un tipo data: si usa una stringa, e per convenzione il formato ISO 8601 (anno-mese-giorno, con l'ora e il fuso se servono). Si ordina bene, non è ambiguo tra formato italiano e americano e ogni linguaggio lo sa leggere.

La A è l'errore classico di chi pensa a SQL o a XSD (che hanno xs:date). La D è quasi vera: il tipo non c'è, ma le date si rappresentano benissimo. La C è pericolosa: 19102026 è ambiguo e non si ordina. Esempio con l'ora: "2026-10-19T08:00:00+02:00". In Java: LocalDate.parse("2026-10-19") e LocalDate.toString() usano proprio ISO 8601.

Al computer · 20 minuti

La tua classe in XML e in JSON

  1. Con un editor (VS Code, Notepad++, Blocco note) crea classe.xml: radice <classe nome="5G">, tre <studente> con id, nome e almeno due voti.
  2. Aprilo nel browser (trascinalo nella finestra): vedi l'albero del documento.
  3. Cancella un tag di chiusura, salva e ricarica: leggi l'errore.
  4. Crea classe.json con gli stessi dati. Nella Console dei DevTools (F12) scrivi JSON.parse(`, incolla il file, chiudi con `) e premi Invio.
  5. Metti in classe-cognome.zip i due file.
Controllo: il browser segnala l'errore XML con la riga (in Chrome "This page contains the following errors", in Firefox "Errore di interpretazione XML"). JSON.parse restituisce un oggetto che puoi espandere; se c'è un errore, ti dice la posizione.
Gli accenti gravi (backtick) servono a incollare testo su più righe in JavaScript. Firefox apre i file .json con un visualizzatore che segnala gli errori anche senza la Console. Errori tipici da cercare girando tra i banchi: virgola dopo l'ultimo studente, voti scritti come "9" (stringa) invece che 9 (numero), nome della radice diverso in apertura e chiusura. Estensione: aggiungere un attributo con il carattere & e vedere che va scritto &amp;.

Descrizione e scoperta

Come so che cosa offre un servizio, e dove trovarlo?

WSDL

Descrizione in XML di un servizio SOAP: operazioni, messaggi, tipi (XSD), indirizzo. Da un WSDL si genera il client in automatico.

OpenAPI

Descrizione in YAML o JSON di un'API REST: percorsi, metodi, parametri, risposte. Nata come Swagger, dal 2016 si chiama OpenAPI.

Cataloghi

Portali per sviluppatori e cataloghi interni delle aziende, con documentazione e chiavi d'accesso.

La scoperta automatica sognata nei primi anni 2000, UDDI, un grande elenco telefonico mondiale dei servizi, non ha funzionato: il registro pubblico di IBM, Microsoft e SAP ha chiuso nel 2006.
UDDI (Universal Description, Discovery and Integration) prevedeva che un programma trovasse da solo il servizio giusto in un registro pubblico e lo usasse. In pratica le aziende non volevano esporre i servizi a sconosciuti e i contratti richiedevano accordi commerciali. È rimasto in qualche registro interno. Curiosità: con gli agenti AI l'idea della scoperta automatica torna di moda; con MCP un'applicazione chiede a un server l'elenco degli strumenti (tools/list) e le loro descrizioni in JSON Schema, e il modello decide quale usare.

Al computer · 15 minuti

Due web service pubblici, due formati

curl "https://api.open-meteo.com/v1/forecast?latitude=45.46&longitude=9.19&current=temperature_2m"
curl https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml
  1. Nel Prompt dei comandi esegui i due comandi (in PowerShell: curl.exe).
  2. Nel JSON di Open-Meteo trova la temperatura attuale a Milano e la sua unità di misura.
  3. Nell'XML della Banca Centrale Europea trova il cambio euro-dollaro e la data.
  4. Ripeti con -i e annota l'header Content-Type delle due risposte.
  5. Salva le risposte e le note in due-formati-cognome.txt.
Controllo: nel JSON c'è un oggetto "current" con "temperature_2m", l'unità è in "current_units". Nell'XML c'è un elemento Cube con currency='USD' e un rate. Il primo Content-Type contiene json, il secondo xml.
Nessuno dei due servizi richiede un account o una chiave. Open-Meteo è un servizio meteo open source; i parametri latitude e longitude sono quelli di Milano (cambiateli con quelli del vostro comune). Il file della BCE è aggiornato ogni giorno lavorativo nel pomeriggio. Le virgolette intorno al primo URL sono necessarie perché la & nel Prompt dei comandi separa i comandi. Se la rete della scuola blocca i siti, il docente esegue i comandi sulla LIM da un hotspot. Domanda: perché la BCE, una grande istituzione, usa ancora XML? (Il servizio esiste da molti anni, molti sistemi bancari lo leggono così: cambiare formato romperebbe i client.)

Al computer · 20 minuti

Un client Java per un web service

import java.net.URI;
import java.net.http.*;
import java.util.regex.*;

public class Meteo {
  public static void main(String[] a) throws Exception {
    String url = "https://api.open-meteo.com/v1/forecast"
        + "?latitude=45.46&longitude=9.19&current=temperature_2m";
    var client = HttpClient.newHttpClient();
    var req = HttpRequest.newBuilder(URI.create(url)).build();
    var r = client.send(req, HttpResponse.BodyHandlers.ofString());
    System.out.println("HTTP " + r.statusCode() + "  "
        + r.headers().firstValue("content-type").orElse("?"));
    Matcher m = Pattern.compile("\"temperature_2m\":(-?[\\d.]+)")
        .matcher(r.body());
    System.out.println(m.find() ? "A Milano ci sono " + m.group(1)
        + " gradi" : "Temperatura non trovata");
  }
}
  1. Scrivi Meteo.java ed eseguilo con java Meteo.java.
  2. Cambia le coordinate con quelle della tua città.
  3. Chiedi anche il vento con current=temperature_2m,wind_speed_10m e stampalo.
Controllo: HTTP 200, un Content-Type con application/json e una temperatura plausibile, per esempio A Milano ci sono 14.3 gradi.
L'espressione regolare cerca il primo "temperature_2m" seguito da un numero: quello in current_units è seguito da una stringa ("°C") e quindi viene saltato. È una scorciatoia didattica: in un progetto vero si usa un parser JSON (per esempio la libreria Jackson o Gson con Maven), perché le espressioni regolari si rompono se il formato cambia anche di poco. Domanda: che cosa succede al programma se il servizio è giù? (client.send lancia un'eccezione: collegare con il laboratorio Riprova della lezione 1.) Soluzione dello step 3: regex analoga con "wind_speed_10m".

Oggi

Chiedere qualcosa a un modello linguistico da un programma è una richiesta HTTP con un corpo JSON: la risposta è un altro JSON con il testo generato e i token usati. OpenAI, Google e Anthropic seguono lo stesso schema.

Oggi

Per farsi rispondere con dati strutturati, si descrivono gli strumenti o il formato atteso con JSON Schema: lo stesso tipo di contratto che usano i web service.

L'esempio segue la documentazione pubblica della Messages API di Anthropic: endpoint /v1/messages, header x-api-key e anthropic-version, corpo con model, max_tokens e messages. Il nome del modello è volutamente generico perché cambia spesso: si trova nella documentazione. La risposta contiene tra l'altro "content": [{"type": "text", "text": "..."}] e "usage" con input_tokens e output_tokens, che determinano il costo. Non far provare agli studenti chiamate con chiavi personali: le API sono a pagamento e la chiave non va mai scritta nel codice o condivisa. Se il docente vuole, mostra una chiamata sulla LIM con la chiave della scuola, dentro una variabile d'ambiente.

Mettiti alla prova

Un'API risponde con l'header Content-Type application/json. Che cosa garantisce?

  1. Niente: è una dichiarazione del server, il client deve comunque controllare
  2. Che il corpo è sicuramente JSON valido
  3. Che il corpo rispetta uno schema JSON
  4. Che i dati sono cifrati durante il viaggio

L'header dice che cosa il server dichiara di mandare. Un server con un bug, o una pagina d'errore di un proxy, può mandare HTML con quell'header. Un client robusto gestisce l'errore di parsing. La cifratura dipende da HTTPS, non dal tipo di contenuto.

Tranello: molti scelgono B. Esempio reale: un proxy aziendale o un gateway che restituisce una pagina HTML di errore, o un servizio che manda un JSON troncato perché la connessione cade. La C confonde il formato con il contratto (lo schema si verifica a parte). Prepara la lezione successiva sugli header HTTP e i tipi MIME.
