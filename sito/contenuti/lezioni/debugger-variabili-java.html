Le variabili

Una variabile è una scatola con nome, tipo e valore

TipoChe cosa contieneBitCome è codificatoEsempio
intnumero intero32complemento a 2: ±2,1 miliardiint n = 16;
doublenumero reale64IEEE 754 doppia precisionedouble m = 7.5;
charun carattere16codice Unicode (UTF-16)char c = 'J';
booleanvero o falso–solo true o falseboolean ok = true;
Java è tipizzato: il tipo si decide quando dichiari la variabile e non cambia più. Il tipo dice quanti bit usare e come leggerli.
Collegare ogni riga alle lezioni precedenti: int = complemento a 2 su 32 bit; double = IEEE 754 a 64 bit; char = codice del carattere (lo approfondiremo nella prossima lezione). Esistono anche byte (8 bit), short (16), long (64) e float (32). La dimensione di boolean non è fissata dalla specifica del linguaggio: per questo il trattino. Il punto e virgola chiude ogni istruzione; il punto, non la virgola, separa i decimali.

Quiz a trabocchetto

int x = 13; double m = x / 2; Quanto vale m?

  1. 6.5
  2. 7.0
  3. Errore di compilazione
  4. 6.0

x e 2 sono int: Java fa la divisione intera (13 / 2 = 6, si butta il resto) e solo dopo mette 6 in un double, che diventa 6.0. Per avere 6.5 serve almeno un operando reale: x / 2.0.

Risposta D. La B è l'errore di chi pensa che Java arrotondi: la divisione intera tronca. La C è l'errore di chi pensa che Java vieti di mettere un int in un double: è una conversione permessa, perché non perde informazione.

Lo strumento

Il debugger: metti in pausa e guarda dentro

Breakpoint

Un punto di stop: il programma si ferma prima di quella riga.

Step over

Esegue la riga corrente e si ferma alla successiva.

Step into

Entra dentro il metodo chiamato in quella riga.

Continue

Riparte fino al prossimo breakpoint.

Mentre il programma è in pausa, il pannello delle variabili locali mostra il valore attuale di ogni variabile. Niente println da aggiungere e poi togliere.
In OnlineGDB: si clicca a sinistra del numero di riga per mettere un breakpoint (pallino), poi si preme Debug invece di Run. In basso compaiono i pulsanti (start, continue, step over, step into, step out) e i pannelli "Local Variables" e "Call Stack". I nomi esatti possono cambiare con gli aggiornamenti del sito: provarlo prima della lezione. Lo stesso modello (breakpoint, step, variabili) vale in VS Code, IntelliJ, Eclipse e NetBeans.

Al computer · 20 minuti

Trova il bug con OnlineGDB

import java.util.Scanner;
public class Main {
  public static void main(String[] args) {
    Scanner in = new Scanner(System.in);
    System.out.print("Fino a che numero? ");
    int n = in.nextInt();
    int somma = 0;
    for (int i = 1; i < n; i++) {
      somma = somma + i;     // breakpoint qui
    }
    System.out.println("Somma: " + somma);
  }
}
  1. Su onlinegdb.com scegli Java e copia il codice.
  2. Metti un breakpoint sulla riga di somma e premi Debug.
  3. Inserisci 10, poi Continue più volte: guarda i e somma.
  4. Correggi e salva in SommaFinoAN.txt.
Controllo: con 10 il programma stampa 45 invece di 55: l'ultimo giro ha i = 9. Correzione: i <= n.
Il ciclo for ripete il corpo per i = 1, 2, … finché la condizione è vera. È il classico errore "di uno" (off-by-one). Somma da 1 a 10 = 55 (formula di Gauss n(n+1)/2). Durante il debug l'input si scrive nella console in basso. Chi finisce prima: provare con n = 100 000 e vedere che succede (5 000 050 000 non sta in un int: overflow, vedi slide seguente).

I limiti di int

Oltre 2 147 483 647 si torna ai negativi

int x = Integer.MAX_VALUE;
System.out.println(x);
x = x + 1;
System.out.println(x);
Output2147483647
-2147483648
È lo stesso overflow del complemento a 2, solo su 32 bit: 0111…1 + 1 = 1000…0. Java non segnala niente. Se servono numeri più grandi si usa long (64 bit).
Integer.MAX_VALUE = 2³¹ − 1. È il limite del contatore di YouTube visto nella lezione sugli interi. In Java esiste Math.addExact(a, b), che lancia un'eccezione in caso di overflow invece di fare il giro: utile da citare ai più curiosi.

Al computer · 15 minuti

A quale numero il fattoriale impazzisce?

public class Main {
  public static void main(String[] args) {
    int f = 1;
    for (int i = 1; i <= 15; i++) {
      f = f * i;
      System.out.println(i + "! = " + f);
    }
  }
}
  1. Esegui con Run in OnlineGDB.
  2. Trova la prima riga sbagliata (n! = 1 · 2 · 3 · … · n).
  3. Cambia int f in long f e riesegui. Salva in Fattoriale.txt.
Controllo: 12! = 479001600 è giusto; 13! stampa 1932053504, ma vale 6227020800. Con long è corretto.
Il controllo si fa a mano: 13! = 12! × 13 = 6 227 020 800, più del massimo di int. Java tiene solo i 32 bit bassi: 6 227 020 800 − 4 294 967 296 = 1 932 053 504. Si può anche usare il debugger con un breakpoint su f = f * i per vedere il momento esatto. Con long si arriva fino a 20!; 21! va di nuovo in overflow.

Mettiti alla prova

Dopo int x = Integer.MAX_VALUE; x++; che cosa succede?

  1. x vale −2147483648
  2. Java lancia un errore e si ferma
  3. x vale 2147483648
  4. x resta 2147483647

Gli int di Java vanno in overflow senza avvisare: 0111…1 + 1 = 1000…0, il valore più negativo. La C è impossibile: 2147483648 non è rappresentabile in un int.

Risposta A. La B è vera per la divisione intera per zero (ArithmeticException), non per l'overflow: confusione frequente. La D è l'idea della "saturazione", che esiste in alcuni processori grafici e audio ma non negli int di Java.

I limiti di double

0.1 + 0.2 visto dal debugger

double z = 0.1 + 0.2;
boolean uguale = (z == 0.3);
boolean vicino =
    Math.abs(z - 0.3) < 1e-9;

In Java Tutor vedi

z 0.30000000000000004

uguale false

vicino true

È la lezione sui numeri reali, dal vivo: il double salva il valore binario più vicino, non 0,3 esatto. Per i confronti usa una tolleranza.
Far incollare queste righe in Java Tutor dentro il main del programma precedente e guardare i valori. Collegamento: per i soldi si usano interi in centesimi o la classe BigDecimal. Domanda: "perché vicino è true?" La differenza è circa 5,5 × 10⁻¹⁷, molto meno di 10⁻⁹.

Casting

Cambiare tipo: a volte da solo, a volte con le parentesi

Allargamento: automatico

int → long → double

double d = 5; // 5.0

Non si perde niente: Java lo fa da solo.

Restringimento: esplicito

Il tipo tra parentesi: (int)

int t = (int) 6.9; // 6

Si può perdere qualcosa: Java vuole la tua firma.

EspressioneRisultatoPerché
(int) -6.9-6tronca verso lo zero, non arrotonda
Math.round(6.7)7per arrotondare c'è un metodo apposito
(byte) 200-56tiene solo 8 bit, letti in complemento a 2
Casting = conversione di tipo. Implicito quando il tipo di arrivo contiene tutti i valori di quello di partenza; esplicito quando potrebbe perdere informazione. Attenzione: Math.round restituisce un long se riceve un double. (byte) 200 lo abbiamo visto nella lezione sugli interi relativi.

Al computer · 15 minuti

Il voto, tagliato e arrotondato

import java.util.Scanner;
public class Main {
  public static void main(String[] args) {
    Scanner in = new Scanner(System.in);
    System.out.print("Voto con decimali: ");
    double voto = in.nextDouble();
    int troncato = (int) voto;
    long arrotondato = Math.round(voto);
    char lettera = (char) ('A' + troncato);
    boolean promosso = arrotondato >= 6;
    System.out.println(troncato + " " + arrotondato
        + " " + lettera + " " + promosso);
  }
}
  1. In OnlineGDB metti un breakpoint sulla riga di troncato e premi Debug.
  2. Inserisci 6.7 (con il punto) e avanza con Step over.
  3. Riprova con 5.5. Salva in Voto.txt.
Controllo: con 6.7 stampa 6 7 G true; con 5.5 stampa 5 6 F true.
Math.round arrotonda la metà verso l'alto: 5.5 → 6. 'A' + 6 = 71 = 'G'; 'A' + 5 = 70 = 'F'. Se Scanner dà InputMismatchException con il punto, il sistema è impostato in italiano: provare 6,7. Su OnlineGDB di solito funziona il punto. Nel pannello delle variabili il char può essere mostrato anche con il suo codice numerico (71 'G'): ottimo spunto per la prossima lezione.

La falena del 1947

Il 9 settembre 1947 il gruppo di Grace Hopper trovò una falena incastrata in un relè del computer Harvard Mark II. Nel registro la incollarono con la nota: "First actual case of bug being found".

La parola "bug" per un guasto si usava già prima: la falena la rese famosa.

Wilkes si riferisce al 1949, quando programmava l'EDSAC a Cambridge. Traduzione nostra dall'inglese ("I can remember the exact instant when I realized that a large part of my life from then on was going to be spent in finding mistakes in my own programs"). La pagina del registro con la falena è conservata allo Smithsonian National Museum of American History. Già Edison, nel 1878, chiamava "bugs" i difetti delle sue invenzioni.
