Che cos'è il software

Una torre a strati, dall'hardware a te

Software applicativo

Risolve un compito dell'utente: scrivere, disegnare, giocare.

Sistema operativo e utility

Gestisce le risorse e offre servizi a tutti i programmi.

Driver e firmware

Parlano con l'hardware; il firmware (UEFI) avvia il PC.

Hardware

Software = programmi + i dati che usano + la documentazione.

Il software di base sono gli strati in basso: fanno funzionare il computer. Quello in alto è applicativo.

Il firmware sta in una memoria non volatile della scheda madre: all'accensione controlla l'hardware e carica il sistema operativo. Le utility (antivirus, compressori, strumenti di backup) stanno a metà: spesso si classificano come software di sistema. Compilatori e ambienti di sviluppo, per chi programma, sono strumenti di sviluppo.

I linguaggi di programmazione

La stessa somma, a tre livelli

Alto livello: Java

int c = a + b;

Vicino al modo di pensare delle persone. Uguale su ogni computer.

Assembly (LMC)

LDA A
ADD B
STA C

Un'istruzione della CPU per riga, con nomi leggibili.

Linguaggio macchina

507
108
309

Solo numeri: codice dell'istruzione e indirizzo della cella.

La CPU capisce solo il linguaggio macchina. Tutto il resto va tradotto.
Riprendere il Little Man Computer della lezione scorsa: LDA (carica) = 5xx, ADD = 1xx, STA (salva) = 3xx; qui supponiamo che A, B, C siano nelle celle 7, 8 e 9. Nei processori veri il linguaggio macchina è in binario e cambia da una famiglia all'altra (x86 nei PC, ARM nei telefoni): per questo un programma compilato per uno non gira sull'altro.

Tradurre

Compilatore o interprete?

Compilatore

Traduce tutto il programma prima di eseguirlo e produce un file eseguibile. Gli errori di sintassi escono subito, tutti insieme.

Esempi: C, C++, Rust.

Interprete

Legge ed esegue il programma un'istruzione alla volta, ogni volta che lo lanci. Un errore salta fuori solo quando ci arriva.

Esempi: Python, i primi BASIC.

Main.java

codice sorgente

javac

compilatore

Main.class

bytecode

JVM

Windows, Mac, Linux, Android…

Java usa una via di mezzo: javac compila in bytecode, un linguaggio macchina "di una CPU immaginaria"; la Java Virtual Machine lo esegue su qualsiasi computer, interpretandolo e compilando al volo le parti più usate (compilazione JIT, just in time). Era lo slogan di Sun nel 1995: "write once, run anywhere". Anche JavaScript nei browser moderni usa interpretazione e compilazione JIT insieme.

Quiz a trabocchetto

Java è compilato o interpretato?

  1. Solo compilato, come il C: si ottiene un .exe
  2. Solo interpretato, riga per riga, come i primi BASIC
  3. Nessuno dei due: la CPU legge direttamente il file .java
  4. Compilato in bytecode, poi eseguito dalla JVM

javac traduce Main.java in Main.class (bytecode, non codice per la tua CPU). Poi la JVM esegue il bytecode, interpretandolo e compilando al volo le parti più usate. Per questo lo stesso .class gira su Windows, Mac e Linux.

La A è il distrattore più scelto da chi conosce un po' di C. La C rivela chi pensa che la CPU capisca il codice sorgente: ricordare la slide dei tre livelli.

Puzzle

Dal codice all'output: metti in ordine

  1. Scrivi il codice nel file Main.java
  2. javac controlla la sintassi e segnala gli errori
  3. javac produce Main.class con il bytecode
  4. Il comando java avvia la JVM
  5. La JVM carica Main.class ed esegue il metodo main
  6. Sullo schermo compare l'output
Su OnlineGDB tutto questo succede premendo Run: il sito compila ed esegue per noi su un server. Errore tipico: invertire le righe 2 e 3. Se c'è un errore di sintassi il file .class non viene prodotto.

Errori di compilazione ed errori di esecuzione

public class Main {
  public static void main(String[] args) {
    int a = 10;
    int b = 0;
    System.out.println("Inizio");
    System.out.println(a / b);
  }
}
  1. Apri onlinegdb.com, in alto a destra scegli Java.
  2. Copia il programma e premi Run. Che cosa viene stampato prima dell'errore?
  3. Togli il ; dopo int a = 10 e premi Run: leggi il messaggio.
  4. Annota i due messaggi in errori-cognome.txt.
Controllo: prima prova: compare "Inizio", poi ArithmeticException: / by zero (errore di esecuzione). Seconda: error: ';' expected con il numero di riga, e non parte niente (errore di compilazione).
Messaggio chiave: l'errore di compilazione blocca tutto prima di partire (nemmeno "Inizio" viene stampato); l'errore di esecuzione arriva a metà, quando il programma tenta l'operazione impossibile. Sfida veloce: cambiare b in 3 e prevedere il risultato (3: divisione intera tra int). Se OnlineGDB non è raggiungibile: usare un altro compilatore online come programiz.com/java-programming/online-compiler, oppure mostrare alla LIM.

Una storia

Grace Hopper e il programma che scrive programmi

Nei primi anni '50 si programmava in codice macchina. Grace Hopper, matematica e ufficiale della Marina degli Stati Uniti, scrisse nel 1952 il sistema A-0, uno dei primi compilatori.

Le dicevano che i computer sapevano solo fare conti, non scrivere programmi. Lei insistette: da quella idea nacque il COBOL (1959), ancora oggi usato da banche ed enti pubblici.

Oggi

Gli assistenti di programmazione con l'AI scrivono codice a partire da una richiesta in italiano. Ma il codice va comunque compilato e provato: a volte usano funzioni che non esistono o sbagliano i casi limite. La responsabilità di controllare resta tua.

Grace Hopper (1906-1992) raccontò più volte che all'inizio nessuno credeva in un compilatore. A lei si deve anche la diffusione del termine "bug" dopo la falena trovata nel 1947 nel computer Mark II (lo hanno visto in prima). Il ponte con l'AI: i modelli linguistici prevedono il codice più probabile, non lo eseguono per controllarlo; per questo possono inventare nomi di funzioni. Nelle lezioni di laboratorio useremo i test per scoprire questi errori.

Le licenze

Che cosa puoi fare con un programma?

TipoCosta?Codice sorgenteEsempi
Proprietario a pagamentoSìChiusoMicrosoft Office, Photoshop, Minecraft
FreewareNoChiusoGoogle Chrome, Zoom (versione base)
Shareware / provaDopo la provaChiusoWinRAR, molti antivirus
Open sourceDi solito noAperto, modificabileLibreOffice (MPL), VLC (GPL), Linux (GPL)
Software liberoDi solito noAperto, con 4 libertàProgrammi GNU (GPL)

La licenza (per i programmi chiusi l'EULA) è il contratto che accetti installando: non compri il programma, compri il diritto di usarlo a certe condizioni.

Le quattro libertà del software libero (Richard Stallman, Free Software Foundation, anni '80): usare il programma per qualsiasi scopo (libertà 0), studiarlo e modificarlo (1), ridistribuirlo (2), distribuire le versioni modificate (3). La GPL è "copyleft": chi distribuisce versioni modificate deve mantenerle libere. Chrome è freeware ma si basa sul progetto open source Chromium. WinRAR: prova gratuita di 40 giorni.

Mettiti alla prova

Un programma gratuito è sempre open source?

  1. Sì: se non lo paghi, il codice è di tutti
  2. No: un freeware è gratis ma il codice resta chiuso
  3. Sì, ma solo se è scaricato da un sito ufficiale
  4. No: l'open source si paga sempre

Gratis e aperto sono due cose diverse. Chrome è gratis ma il suo codice non è pubblico; un programma open source può anche essere venduto, purché si rispetti la licenza. "Free" in "free software" vuol dire libero, non gratuito.

Citare la frase della Free Software Foundation: "free" come in "libertà di parola", non come in "birra gratis" (free speech, not free beer). Esempio di open source venduto: distribuzioni Linux aziendali con assistenza a pagamento, come Red Hat Enterprise Linux.

Licenze e AI

"Open source" anche per i modelli di AI?

Modelli chiusi

Si usano solo attraverso un sito o un'app dell'azienda. Non si scaricano.

Modelli "a pesi aperti"

Si possono scaricare i pesi (i numeri imparati) e farli girare sul proprio computer.

Oggi

Alcuni modelli scaricabili hanno licenze con limiti d'uso, e quasi mai si pubblicano i dati di addestramento. Per questo si parla di open weights (pesi aperti) e non sempre di open source. Prima di usare un modello in un progetto, come per ogni software, si legge la licenza.

Esempi di licenze diverse: alcuni modelli sono pubblicati con licenza Apache 2.0, altri con licenze proprie che vietano certi usi o pongono limiti alle grandi aziende. La Open Source Initiative ha pubblicato nel 2024 una definizione di "open source AI" che chiede anche informazioni dettagliate sui dati. Restare sul concetto, senza giudizi sui singoli prodotti.
