UDA 7 · Funzioni e array in C e C++

La ricerca
in un vettore

C'è o non c'è? Dove si trova? Quante volte compare? Impariamo a cercare come fa un computer: una cella alla volta.

Obiettivi: capire e scrivere la ricerca sequenziale (con for e return, o con while e variabile trovato), contare i confronti, analizzare un vettore (conteggio delle occorrenze, posizioni) e modificarne i dati (sostituzione). Assaggio della ricerca dicotomica come sfida. Durata indicativa: 2-3 ore. Prerequisiti: vettori e funzioni con i vettori.

Per cominciare

Hai perso le chiavi in casa. Come le cerchi?

  1. Stanza per stanza, senza saltarne nessuna
  2. Prima nei posti dove le lascio di solito
  3. Chiedo a qualcuno di casa
  4. Aspetto che saltino fuori da sole
Sondaggio senza risposta giusta. La A è la ricerca sequenziale: lenta ma sicura, se le chiavi ci sono le trovi. La B funziona solo se c'è un ordine o un'abitudine: è l'idea della ricerca "furba" su dati ordinati (dicotomica), che assaggeremo alla fine. Il computer, senza informazioni sui dati, fa come nella A.

La ricerca sequenziale

Cerchiamo il 9, una cella alla volta

4i = 0 7i = 1 1i = 2 9i = 3 3i = 4 8i = 5

Trovato

Al quarto confronto v[3] == 9: ci si ferma e si restituisce la posizione.

Non trovato

Se cerchi il 5 arrivi in fondo: 6 confronti, poi la risposta "non c'è".

Far fare la ricerca a voce: uno studente "è" il computer e può guardare una sola cella alla volta (si possono usare 6 fogli girati sul banco). Domanda: se il valore cercato è nel vettore due volte, quale posizione trova la ricerca? La prima, perché si ferma subito.

Puzzle

Metti in ordine i passi della ricerca sequenziale

  1. Leggi il valore x da cercare
  2. Parti dalla prima cella, i = 0, con trovato = falso
  3. Confronta v[i] con x
  4. Se sono uguali, trovato diventa vero e ti fermi
  5. Altrimenti passa alla cella successiva, i++
  6. Se arrivi in fondo senza trovarlo, stampa "non presente"
Ordine giusto come scritto. Errore tipico: mettere "non presente" subito dopo il primo confronto sbagliato. Si può dire che non c'è solo dopo aver controllato TUTTE le celle: è lo stesso errore del quiz che vedremo tra poco.

La ricerca in C

Due modi di scriverla

Funzione con for e return

int cerca(int v[], int n, int x) {
    for (int i = 0; i < n; i++)
        if (v[i] == x)
            return i;  // trovato
    return -1;        // non c'è
}

Ciclo while con "trovato"

int i = 0, trovato = 0;
while (i < N && !trovato) {
    if (v[i] == x) trovato = 1;
    else i++;
}
if (trovato) printf("Posizione %d", i);
else printf("Non presente");
Perché -1? Perché nessuna cella ha indice -1: chi chiama la funzione capisce subito che il valore non c'è.
Entrambe le versioni sono state verificate con gcc. La prima è più compatta: return esce subito dalla funzione (ricordate il quiz sul return). La seconda è quella "da diagramma di flusso": la condizione del while ha due parti, ci si ferma se si arriva in fondo OPPURE se si è trovato. !trovato si legge "non trovato". In C++ il codice è identico, cambia solo l'output con cout.

Puzzle · Traccia la ricerca

Al primo confronto i vale e v[i] vale .

La ricerca si ferma quando i vale .

In tutto si fanno confronti.

Soluzioni: 0 e 5; 2; 3 confronti; 5 confronti e -1; il 2 compare in posizione 1 e in posizione 3, ma la ricerca si ferma alla prima, quindi 1. Verificato con gcc. Far lavorare a coppie: uno legge il codice, l'altro aggiorna una tabellina i, v[i], uguale?

Al computer · 15 minuti

Il buttafuori della festa

  1. In C crea la lista degli invitati: int lista[8] = {105, 230, 318, 422, 507, 615, 733, 849}; (sono i numeri dei biglietti).
  2. Scrivi la funzione int cerca(int v[], int n, int x).
  3. Nel main leggi un numero di biglietto e chiama cerca.
  4. Se c'è, stampa Benvenuto! Sei in lista, posizione seguito dalla posizione (indice + 1); se no, Non sei in lista.
  5. Salva come buttafuori.c.
Controllo: 422 dà posizione 4; 105 dà posizione 1; 500 dà Non sei in lista.
Soluzione nel main: int p = cerca(lista, 8, x); if (p >= 0) printf("Benvenuto! Sei in lista, posizione %d\n", p + 1); else printf("Non sei in lista\n"); Verificato con gcc. Per chi finisce prima: ripetere la domanda con un ciclo finché non si inserisce 0, e contare quanti ospiti sono entrati.

Quiz a trabocchetto

Con v = {4, 7, 1, 9}, quanto vale cerca(v, 4, 9)?

int cerca(int v[], int n, int x) {
    for (int i = 0; i < n; i++) {
        if (v[i] == x) return i;
        else return -1;
    }
    return -1;
}
  1. 3
  2. 4
  3. -1
  4. 9

Al primo giro v[0] = 4 è diverso da 9: parte l'else e return -1 chiude subito la funzione. Le altre celle non vengono mai guardate.

Verificato con gcc: restituisce -1. È il bug più comune nella ricerca: decidere "non c'è" dopo un solo confronto. Correzione: togliere l'else; il return -1 va solo DOPO il ciclo. Chi risponde 3 legge il codice come dovrebbe essere, non come è scritto: ottima occasione per dire "il computer fa quello che scrivi, non quello che pensi".

Quiz

Vettore di 1000 numeri: quanti confronti, nel caso peggiore?

  1. 1000
  2. 500
  3. 10
  4. 1

Il caso peggiore è quando il valore è nell'ultima cella o non c'è: bisogna confrontarle tutte. In media, se il valore c'è, ne servono circa la metà.

500 è la media (se il valore è presente in una posizione a caso), non il caso peggiore. 10 è il numero di confronti della ricerca dicotomica su 1000 elementi ordinati: lo vedremo nella sfida finale. Il caso migliore è 1 confronto: il valore è nella prima cella. Dire che la ricerca sequenziale ha un costo "proporzionale a n": se i dati raddoppiano, raddoppia il tempo.

Analisi dei dati

Contare: quante volte compare?

int conta(int v[], int n, int x) {
    int c = 0;
    for (int i = 0; i < n; i++)
        if (v[i] == x)
            c++;
    return c;
}

Qui non ci si ferma al primo trovato: bisogna guardare tutte le celle.

Con {2, 5, 2, 8} la chiamata conta(v, 4, 2) restituisce 2.

Verificato con gcc. È il contatore della UDA 5 e 6 applicato a un vettore. Varianti da chiedere a voce: contare i voti sufficienti (v[i] >= 6), contare i numeri pari (v[i] % 2 == 0), trovare l'ultima posizione di x (si scorre tutto e si aggiorna una variabile pos a ogni trovato).

Modifica dei dati

Cerca e sostituisci

void sostituisci(int v[], int n,
                 int vecchio, int nuovo) {
    for (int i = 0; i < n; i++)
        if (v[i] == vecchio)
            v[i] = nuovo;
}
// sostituisci(a, 6, 0, 1);

Prima

Dopo

Verificato con gcc: {3, 0, 5, 0, 0, 2} diventa {3, 1, 5, 1, 1, 2}. È proprio il "Trova e sostituisci" di Writer applicato ai numeri. La funzione è void ma il vettore cambia davvero: il vettore passa per indirizzo (lezione precedente).

Al computer · 20 minuti

Il registro della verifica

  1. In C scrivi int voti[12] = {6, 7, 4, 8, 6, 5, 9, 6, 4, 7, 6, 10};
  2. Con la funzione conta stampa quanti 6 ci sono.
  3. Con un ciclo stampa il numero di ogni studente che ha preso 4 (indice + 1).
  4. La prof alza i 4 a 5: usa sostituisci e stampa il vettore aggiornato.
  5. Salva come registro-ricerca.c.
Controllo: i 6 sono 4; hanno preso 4 gli studenti 3 e 9; dopo la modifica il vettore è 6 7 5 8 6 5 9 6 5 7 6 10.
Tutti i risultati sono stati verificati con gcc. Per il punto 3: for (int i = 0; i < 12; i++) if (voti[i] == 4) printf("Studente %d\n", i + 1); Per chi finisce prima: scrivere int ultima(int v[], int n, int x) che restituisce l'ultima posizione di x (per il 6 deve dare l'indice 10, cioè lo studente 11).

Gli algoritmi si capiscono provandoli

Oggi

Quando premi Ctrl+F in una pagina web, il browser cerca il testo pezzo per pezzo, proprio come la ricerca sequenziale. Un motore di ricerca invece non può scorrere tutto il web a ogni domanda: prepara prima un indice, come quello in fondo a un libro.

Traduzione nostra dall'inglese: "An algorithm must be seen to be believed, and the best way to learn what an algorithm is all about is to try it." D. Knuth, The Art of Computer Programming, vol. 1, sezione 1.1 (1968). Il volume 3 della stessa opera (1973) si intitola proprio "Sorting and Searching", ordinare e cercare: i due argomenti di queste ultime lezioni. Sui motori di ricerca: l'indice dice, per ogni parola, in quali pagine compare, così la risposta arriva in una frazione di secondo.

Al computer · 15 minuti

Andiamo oltre: il computer indovina il tuo numero

  1. Su OnlineGDB scegli C++. Usa basso = 1 e alto = 100.
  2. In un ciclo while il computer prova (basso + alto) / 2 e chiede: 0 = giusto, 1 = più grande, 2 = più piccolo.
  3. Se è più grande: basso = prova + 1; se è più piccolo: alto = prova - 1.
  4. Conta i tentativi e stampali alla fine. Salva come indovino.cpp.
Controllo: qualunque numero da 1 a 100 viene indovinato in 7 tentativi al massimo. Pensa 63: le prove sono 50, 75, 62, 68, 65, 63.
È la ricerca dicotomica (o binaria): a ogni domanda si scarta metà dei numeri rimasti. 7 tentativi bastano perché 2^7 = 128 è più di 100 (verificato provando tutti i numeri da 1 a 100). Funziona solo perché i numeri da 1 a 100 sono ORDINATI: in un vettore disordinato non si può fare, ed è uno dei motivi per cui nella prossima lezione impariamo a ordinare. Collegamento con il gioco "indovina il numero" della UDA 6, dove era l'utente a indovinare.

Oggi

Alcuni assistenti AI, prima di rispondere, cercano nei documenti i pezzi più adatti alla domanda e poi scrivono la risposta usandoli. Si chiama RAG: senza una ricerca veloce, su milioni di documenti, sarebbe impossibile.

I numeri della dicotomica sono le potenze di 2: 2^7 = 128 ≥ 100, 2^10 = 1024 ≥ 1000, 2^20 = 1 048 576 ≥ 1 000 000. RAG sta per Retrieval-Augmented Generation (generazione aumentata dal recupero di informazioni): per trovare i pezzi simili si confrontano i vettori di numeri (embedding) visti nella lezione sui vettori, con indici speciali molto più veloci della ricerca sequenziale.

Sfida finale

Apri il lucchetto con la ricerca

  • 1ª cifra: con v = {4, 7, 1, 9, 3}, il valore restituito da cerca(v, 5, 9)
  • 2ª cifra: quante volte compare il 2 in {2, 5, 2, 8}
  • 3ª cifra: quanti confronti servono per trovare il 7 in {7, 1, 4}
  • 4ª cifra: i tentativi massimi per indovinare un numero da 1 a 100 dimezzando
Lucchetto aperto! Il 9 ha indice 3, il 2 compare 2 volte, il 7 è nella prima cella (1 confronto), la dicotomica ne usa al massimo 7.
Codice: 3217. Tranello sulla prima cifra: la funzione restituisce l'indice (3), non la posizione "umana" (4).
