Al computer · 15 minuti

Tappa 1: la calcolatrice mostra tutte le basi

  1. Apri la Calcolatrice, menu ☰, modalità Programmatore. Clicca su DEC e scrivi 2026.
  2. Leggi le righe HEX, OCT e BIN e copiale in lab-numeri-cognome.txt.
  3. Passa al tastierino dei bit (l'icona con i puntini): clicca sui bit per ottenere 1010 1010. Che numero è in DEC e in HEX?
  4. Ora accendi solo il bit che vale 1024: che cosa compare?
Controllo: 2026 = HEX 7EA, OCT 3 752, BIN 0111 1110 1010. 1010 1010 = 170 = AA. Il bit 10 acceso dà 1024 = 400 in esadecimale.
La calcolatrice raggruppa le cifre per leggibilità: a 4 a 4 in binario e a 3 a 3 in ottale. Nel tastierino dei bit le posizioni sono numerate da 0 (a destra) a 63: il bit numero 10 vale 2¹⁰ = 1024. 170 = 128 + 32 + 8 + 2. Domanda: perché AA? Ogni gruppo 1010 vale A. Lasciare la modalità QWORD (64 bit): le altre (DWORD, WORD, BYTE) le useremo con i numeri negativi.

Al computer · 10 minuti

Somme e scorrimenti in binario

  1. In modalità BIN calcola 1011 0110 + 0110 1011. Prima prevedi il risultato su carta.
  2. Scrivi 101, poi usa lo scorrimento a sinistra di 1 posto (<<, nel menu degli scorrimenti di bit) e premi =. Ripeti 3 volte e guarda DEC.
  3. Fai lo stesso con lo scorrimento a destra (>>) partendo da 100 (DEC).
  4. Annota i risultati e la regola che hai scoperto.
Controllo: la somma è 1 0010 0001 (182 + 107 = 289). Spostare a sinistra raddoppia: 5, 10, 20, 40. A destra dimezza senza resto: 100, 50, 25, 12.
Nella Calcolatrice di Windows 10/11 il pulsante "Spostamento bit" (Bit shift) apre le opzioni; il tasto << chiede il numero di posizioni dopo l'operatore: scrivere 101 << 1 =. La somma supera 255: servono 9 bit, primo assaggio di overflow con 8 bit. 25 >> 1 = 12: l'ultimo bit (1) si perde, come la divisione intera. Se la calcolatrice non c'è: la console con 0b101 << 1.

Mettiti alla prova

Sullo schermo c'è 0000 0101. Sposti a sinistra di 1. Che cosa leggi?

  1. 0000 0010, cioè 2
  2. 0000 1010, cioè 10
  3. 1010 0000, cioè 160
  4. 0000 0110, cioè 6

Ogni bit si sposta di un posto verso sinistra e a destra entra uno 0: 101 diventa 1010, il valore raddoppia. Come in decimale aggiungere uno 0 moltiplica per 10.

La A è lo spostamento a destra (dimezzare); la C è chi sposta di 4 posti, cioè di un'intera cifra esadecimale (moltiplica per 16); la D è chi fa "+1". Gli scorrimenti esistono anche in Java: 5 << 1 vale 10.

Quiz a trabocchetto

Che cosa restituisce parseInt("102", 2)?

  1. NaN, perché 2 non è una cifra binaria
  2. 102
  3. Un errore scritto in rosso
  4. 2

parseInt legge da sinistra e si ferma alla prima cifra non valida, senza errori: legge "10" e si ferma al 2. 10 in binario vale 2. Restituisce NaN solo se già il primo carattere non è valido, come in parseInt("2", 2).

Provarlo subito in console dopo il voto. È un esempio di comportamento "silenzioso" pericoloso: il programma non segnala l'errore e dà un risultato sbagliato. Nel nostro convertitore Java (sfida finale) controlleremo ogni cifra e diremo chiaramente "cifra non valida". In Java Integer.parseInt("102", 2) invece lancia una NumberFormatException: un comportamento più severo.

Tappa 3 · Java

La libreria di Java converte già

import java.util.Scanner;

public class Main {
  public static void main(String[] args) {
    Scanner in = new Scanner(System.in);
    System.out.print("Numero decimale: ");
    int n = in.nextInt();
    System.out.println("Binario:     " + Integer.toBinaryString(n));
    System.out.println("Ottale:      " + Integer.toOctalString(n));
    System.out.println("Esadecimale: " + Integer.toHexString(n));
    System.out.println("Base 3:      " + Integer.toString(n, 3));
    System.out.println("7EA in dec:  " + Integer.parseInt("7EA", 16));
  }
}

Da decimale

toBinaryString(n)
toOctalString(n)
toHexString(n)
toString(n, base)

Verso decimale

parseInt(testo, base)

Integer è una classe della libreria standard di Java: non serve import. Scanner invece va importato. I metodi restituiscono String: il risultato è un testo, non un numero (come le virgolette nella console). toString(n, base) funziona da base 2 a base 36 (cifre 0–9 e A–Z).

Il risultato con -1 è voluto: è il ponte verso la prossima lezione (rappresentazione dei numeri interi relativi, complemento a due). Un int in Java ha 32 bit; -1 in complemento a due sono 32 uni. Notare che toString(-1, 3) stampa invece "-1": quel metodo mette il segno davanti, gli altri mostrano i bit. Lasciare la curiosità aperta. Ora l'algoritmo lo scriviamo noi

Divisioni successive, in Java

import java.util.Scanner;
public class Main {
  public static void main(String[] args) {
    Scanner in = new Scanner(System.in);
    int n = in.nextInt();     // il numero
    int b = in.nextInt();     // la base, da 2 a 16
    String cifre = "0123456789ABCDEF";
    String risultato = "";
    int q = n;
    do {
      int resto = q % b;
      risultato = cifre.charAt(resto) + risultato;
      q = q / b;
    } while (q > 0);
    System.out.println(n + " in base " + b + " = " + risultato);
  }
}
  • % dà il resto, / tra int il quoziente.
  • charAt(resto) trasforma il resto 10 in A, 15 in F.
  • La cifra si attacca davanti: così i resti escono già dal basso verso l'alto.
Far leggere il codice ad alta voce a uno studente, riga per riga, collegando ogni riga al metodo su carta. La riga evidenziata è il cuore: mettere la nuova cifra a sinistra equivale a "leggere i resti dal basso". Domanda: perché do-while e non while? Lo scopriremo con il caso n = 0.

Puzzle

Rimetti in ordine l'algoritmo

  1. Leggi il numero n e la base b
  2. Parti con un risultato vuoto e con q = n
  3. Calcola il resto di q diviso b
  4. Metti la cifra del resto davanti al risultato
  5. Sostituisci q con il quoziente q / b
  6. Se q è maggiore di 0 torna al resto, altrimenti stampa
A coppie, senza guardare la slide precedente. Errore tipico: aggiornare q prima di calcolare il resto (si perde la cifra delle unità). Collegare alla prossima unità sullo sviluppo del software: questo è l'algoritmo, il codice è una sua traduzione.

Al computer · 25 minuti

Sfida a coppie: il convertitore al contrario

Scrivi un programma che legge un testo e una base e stampa il valore decimale. Idea (schema di Horner): per ogni cifra, da sinistra,

valore = valore · b + cifra
  1. Il valore di una cifra: cifre.indexOf(s.charAt(i)).
  2. Se la cifra non esiste o è ≥ b, stampa Cifra non valida e fermati.
  3. Consegna su Novaula convertitore-cognome.java.
Controllo: 7EA 16 → 2026; 10201 3 → 100; 1101 2 → 13; 709 8 → Cifra non valida: 9. Con 7ea 16 (minuscolo) deve funzionare lo stesso.
Soluzione (testata): leggere String s = in.next().toUpperCase(); int b = in.nextInt(); int valore = 0; for (int i = 0; i < s.length(); i++) { int c = cifre.indexOf(s.charAt(i)); if (c < 0 || c >= b) { System.out.println("Cifra non valida: " + s.charAt(i)); return; } valore = valore * b + c; } poi stampare. Horner a mano: 7EA → 7; 7·16 + 14 = 126; 126·16 + 10 = 2026. toUpperCase gestisce le minuscole. Diversamente da parseInt della console, il nostro programma non si ferma in silenzio. Si completa a casa se non basta il tempo: è il compito collegato.
