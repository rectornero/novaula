Unità 7 · Il sistema operativo come gestore di risorse

Il file system

Il disco è solo una lunga fila di blocchi numerati. Chi trasforma quei blocchi in cartelle, nomi, percorsi e permessi? E perché un file da 5 GB non entra in una chiavetta mezza vuota?

Obiettivi: capire che cos'è un file system e quali informazioni conserva su ogni file (metadati); scrivere percorsi assoluti e relativi in Windows e in Linux; leggere e impostare i permessi rwx di Linux, anche in notazione ottale con chmod; confrontare NTFS, FAT32, exFAT ed ext4. Durata indicativa: 2 ore. Servono i PC del laboratorio con Windows ed Esplora file, e il browser per JSLinux (bellard.org/jslinux): verificare prima della lezione che il sito si apra dalla rete della scuola. Utile una chiavetta USB per la prima attività.

Che cos'è

Il file system è il catalogo del disco

Il disco conosce solo blocchi numerati. Il file system è la parte del sistema operativo che li organizza in file e cartelle con un nome.

  • File: sequenza di byte con un nome
  • Cartella (directory): un file speciale che elenca altri file
  • Per ogni file conserva i metadati: dimensione, date, proprietario, permessi, dove stanno i blocchi

Collegare all'unità 6: il sistema operativo gestisce le risorse, e il disco è una risorsa condivisa da tutti i programmi. Il programma non scrive "nel blocco 51 234": chiede "apri tema.odt" con una chiamata di sistema, e il file system traduce. Esempio di metadati: clic destro su un file, Proprietà, scheda Generale (dimensione, date di creazione, modifica, ultimo accesso). Nella lezione online successiva vedremo come il file system tiene traccia dei blocchi (FAT, i-node).

Menti che ci hanno preceduto

Unix, 1974: tutto parte dal file system

Le loro idee sono ancora qui: un unico albero di cartelle che parte da /, i percorsi con la barra, i permessi rwx. Linux, macOS e Android le hanno ereditate.

La traduzione è nostra; l'originale apre la sezione III dell'articolo pubblicato su Communications of the ACM nel 1974: "The most important role of the system is to provide a file system." Il testo è sul sito di Dennis Ritchie ospitato da Nokia Bell Labs. Ritchie è anche l'autore del linguaggio C. Domanda alla classe: perché proprio il file system e non, per esempio, la grafica? (Nel 1974 non c'era grafica: il lavoro di tutti erano file di testo, programmi e dati.)

Percorsi

Lo stesso file, due sistemi, due modi di scriverlo

Windows

C:\Users\anna\Documents\tema.odt

Una radice per ogni unità (C:, D:, E:…), separatore \, maiuscole e minuscole uguali.

Linux e macOS

/home/anna/documenti/tema.odt

Un'unica radice /, separatore /, Tema.odt e tema.odt sono due file diversi.

Assoluto

parte dalla radice: vale ovunque tu sia

Relativo

parte da dove sei: foto/gita.jpg

Scorciatoie

. qui · .. su di uno · ~ la tua home

Far notare che Windows mostra "Documenti" ma la cartella vera si chiama Documents: il nome tradotto è solo un'etichetta di visualizzazione (lo vedranno nel laboratorio). La distinzione maiuscole/minuscole su macOS dipende dalla formattazione (di solito non distingue), su Linux distingue sempre. In Windows anche i percorsi relativi funzionano (nel prompt dei comandi cd .. esiste). Sul web gli URL usano la barra / come Unix: collegamento con l'unità 4.

Mettiti alla prova

Sei in /home/anna/scuola. Dove ti porta cd ../foto/gita?

  1. /home/anna/scuola/foto/gita
  2. /home/anna/foto/gita
  3. /foto/gita
  4. /home/foto/gita

Il percorso è relativo: .. sale di un livello, da /home/anna/scuola a /home/anna; poi si scende in foto e in gita. Risultato: /home/anna/foto/gita.

La A è l'errore di chi ignora i due punti; la C di chi pensa che il percorso parta dalla radice (ma non inizia con /); la D di chi sale di due livelli. Far disegnare l'albero alla lavagna e seguire il percorso con il dito.

Al computer · 15 minuti

Il vero indirizzo dei tuoi file

  1. In Esplora file, in Documenti, crea la cartella TPSI e dentro la cartella U7.
  2. In U7: clic destro, Nuovo, Documento di testo, chiamalo percorsi.txt.
  3. Seleziona il file, tieni premuto Maiusc e fai clic destro: scegli Copia come percorso. Incollalo dentro il file.
  4. In Questo PC, clic destro sul disco C:, Proprietà: annota nel file la voce File system. Se hai una chiavetta, fai lo stesso.
  5. Scrivi il percorso relativo del file partendo dalla cartella Documents. Salva.
Controllo: il percorso inizia con C:\Users\ e finisce con \TPSI\U7\percorsi.txt. Sorpresa: Esplora file mostra "Documenti", ma nel percorso compare Documents. Il disco C: è NTFS.
Soluzione tipica: "C:\Users\nome\Documents\TPSI\U7\percorsi.txt" (con le virgolette, che Windows aggiunge). Percorso relativo da Documents: TPSI\U7\percorsi.txt. Se il PC salva Documenti su OneDrive il percorso è del tipo C:\Users\nome\OneDrive\Documents\…; su un PC di dominio può comparire una cartella di rete: va bene lo stesso, discuterne. In Windows 11 "Copia come percorso" è anche nel menu normale (Ctrl+Maiusc+C). Le chiavette sono di solito FAT32 (fino a 32 GB) o exFAT (più grandi): tenerne a mente il risultato per la slide sui file system.

Al computer · 15 minuti

Muoversi nell'albero di Linux

  1. Vai su bellard.org/jslinux e avvia la console Alpine Linux. Aspetta il prompt localhost:~#.
  2. Crea tre cartelle in un colpo: mkdir -p scuola/tpsi/u7, poi cd scuola/tpsi/u7 e pwd.
  3. Sali: cd .. e pwd. Salta con un percorso assoluto: cd /etc e pwd. Torna a casa: cd ~.
  4. Guarda la radice: ls /. Riconosci home, etc, dev?
  5. Prima di premere Invio, scrivi su percorsi-linux.txt (Blocco note) dove ti porterà cd scuola/tpsi/../tpsi/u7. Poi verifica con pwd.
Controllo: il primo pwd stampa /root/scuola/tpsi/u7, il secondo /root/scuola/tpsi. Dopo cd ~ sei in /root: in JSLinux sei l'utente root.
JSLinux (Fabrice Bellard) emula un PC completo nel browser: nessun account, nessuna installazione; ricaricando la pagina tutto si azzera. Il comando dell'ultimo punto porta in /root/scuola/tpsi/u7: ".." annulla il "tpsi" precedente. Le cartelle della radice: /home case degli utenti, /etc configurazioni, /dev periferiche (le ritroveremo nella lezione sulle periferiche), /bin programmi. Se il sito è bloccato: alternativa copy.sh/v86 (immagini Linux nel browser) oppure demo alla LIM.

Permessi

Chi può fare che cosa: leggere ls -l

-rwxr-x---  1 anna classe3e  512 ott 19 10:15 verifica.sh

rwx · proprietario

anna può leggere, scrivere ed eseguire

r-x · gruppo

chi è nel gruppo classe3e legge ed esegue

--- · altri

tutti gli altri: niente

r = leggere · w = scrivere (modificare, cancellare) · x = eseguire. Il primo carattere dice il tipo: - file, d cartella.

Sulle cartelle il significato cambia: r = vedere l'elenco dei file, w = creare o cancellare file dentro, x = poterci entrare (cd). Il numero 1 è il conteggio dei collegamenti (link), lo riprenderemo con gli i-node. Windows usa un sistema più ricco, le ACL di NTFS (scheda Sicurezza nelle proprietà), che vedremo nella lezione sulla protezione dei dati.

Da lettere a numeri

Tre bit per gruppo: i permessi sono ottali

r = 4 · w = 2 · x = 1, si sommano per ogni grupporwx r-x r-- = 7 5 4

Ogni gruppo è un numero binario di 3 bit: r-x = 101₂ = 5. Tre gruppi, tre cifre ottali: lo avete già visto con l'esadecimale.

LettereBitOttale
rwx1117
rw-1106
r-x1015
r--1004
---0000
Collegamento con l'unità 1: una cifra ottale = 3 bit, come una cifra esadecimale = 4 bit. Esempi da fare a voce: 644 = rw-r--r-- (documenti), 755 = rwxr-xr-x (programmi e cartelle), 600 = rw------- (file privati, per esempio le chiavi SSH), 777 = tutto a tutti (quasi sempre un errore). Le combinazioni 3 (-wx), 2 (-w-) e 1 (--x) esistono ma si usano poco.

Puzzle

Abbina ogni numero ai suoi permessi

755
rwxr-xr-x: tutti eseguono, solo il proprietario modifica
644
rw-r--r--: tutti leggono, solo il proprietario scrive
600
rw-------: file privato del proprietario
750
rwxr-x---: il gruppo esegue, gli altri niente
777
rwxrwxrwx: chiunque può anche cancellare
Da fare a squadre di due: prima a mente, poi si controlla. Chiedere per 777 perché è pericoloso: qualunque utente (o programma malevolo che gira con un altro utente) può modificare o sostituire il file. Domanda bonus: che numero ha rw-rw-r--? (664)

Quiz

chmod 640 voti.ods: che cosa può fare il gruppo?

  1. Leggere e scrivere
  2. Niente
  3. Leggere, scrivere ed eseguire
  4. Solo leggere

640 = rw- r-- ---. La seconda cifra, 4, è del gruppo: 4 = r, solo lettura. Il proprietario (6) legge e scrive, gli altri (0) non fanno niente.

Chi sceglie A ha letto la prima cifra (proprietario); chi sceglie B ha letto l'ultima (altri). Ripetere l'ordine: proprietario, gruppo, altri (in inglese user, group, other: ugo).

Al computer · 20 minuti

chmod in azione: rendi eseguibile uno script

  1. In JSLinux: cd ~/scuola/tpsi/u7 (se hai ricaricato la pagina, prima mkdir -p).
  2. Crea uno script: echo 'echo Ciao dal file system' > saluta.sh
  3. ls -l saluta.sh: annota i permessi. Prova a eseguirlo: ./saluta.sh
  4. chmod 755 saluta.sh, di nuovo ls -l e ./saluta.sh.
  5. Prevedi le lettere di chmod 640 saluta.sh, poi verifica con ls -l.
  6. Fai uno screenshot della console e salvalo come chmod-cognome.png.
Controllo: all'inizio -rw-r--r-- (644) e Permission denied. Dopo 755: -rwxr-xr-x e compare Ciao dal file system. Dopo 640: -rw-r-----.
I file nuovi nascono con 644 perché la maschera predefinita (umask) è 022. Curiosità importante: in JSLinux siete root, e root ignora i permessi r e w (può leggere anche un file 000); però non può eseguire un file che non ha nessuna x: per questo lo script viene rifiutato anche a root. Si può dimostrare: chmod 000 saluta.sh, poi cat saluta.sh funziona lo stesso. Esiste anche la forma simbolica: chmod u+x saluta.sh, chmod go-r voti.ods. Se JSLinux non va: copy.sh/v86 oppure demo alla LIM.

Tre domande da veri amministratori

Cartella con r ma senza x

Che cosa puoi fare?

Vedi i nomi dei file con ls, ma non puoi entrarci con cd né aprire i file.

Un file 444

Puoi cancellarlo?

Sì, se hai w sulla cartella: cancellare un file vuol dire modificare la cartella che lo elenca.

L'utente root

Rispetta i permessi?

Quasi mai: legge e scrive tutto. Per questo si usa root solo quando serve, con sudo.

La seconda carta sorprende quasi tutti e mostra che una cartella è a sua volta un file con i suoi permessi. Collegamento con il principio del minimo privilegio, che riprenderemo nella lezione sulla protezione dei dati: anche voi a casa dovreste usare un account normale, non amministratore.

Quattro formati, quattro mestieri

Journaling: prima di modificare il disco il file system annota che cosa sta per fare in un diario. Se va via la corrente, al riavvio rilegge il diario e non resta a metà.

Date: FAT32 con Windows 95 OSR2 (1996); exFAT di Microsoft (2006), obbligatorio per le schede SDXC; NTFS con Windows NT 3.1 (1993); ext4 stabile nel kernel Linux dalla fine del 2008. Il limite di ext4 vale con blocchi da 4 KB (16 TiB). macOS usa APFS (2017). Compatibilità: Windows non legge ext4 da solo; macOS legge NTFS ma di base non lo scrive; FAT32 ed exFAT li leggono tutti. Per questo le chiavette usano FAT32 o exFAT. Ricollegarsi ai risultati del primo laboratorio.

Quiz a trabocchetto

La chiavetta ha 20 GB liberi, ma il video da 5 GB non si copia. Perché?

  1. La chiavetta è FAT32: un file non può superare i 4 GB
  2. Lo spazio libero indicato da Windows non è reale
  3. Il video è danneggiato e Windows lo blocca
  4. Va formattata in ext4, il formato per i file grandi

In FAT32 la dimensione di un file è scritta in 32 bit: al massimo 2³² − 1 byte, circa 4 GB. Lo spazio c'è, ma il formato non sa descrivere quel file. Soluzione: formattare in exFAT (o NTFS), dopo aver salvato i dati.

Il tranello è la D: ext4 accetterebbe il file, ma poi Windows non leggerebbe la chiavetta. Il messaggio di Windows in questo caso è "Il file è troppo grande per il file system di destinazione". Calcolo: 2³² = 4 294 967 296 byte = 4 GiB. Ricordare: formattare cancella tutto.

Una cassaforte per ogni app

Android è costruito su Linux e dà a ogni app installata un utente Linux tutto suo, con una cartella privata. I permessi rwx impediscono a un'app di leggere i file di un'altra: è la "sandbox" delle app.

Oggi

Agenti AI e file

Gli assistenti AI per programmatori possono leggere file ed eseguire comandi sul PC. Quelli seri lavorano con permessi limitati e chiedono conferma prima di modificare o cancellare: è lo stesso principio dei permessi di Unix.

Android: ogni app riceve un UID (identificativo utente) Linux diverso all'installazione; la documentazione ufficiale per sviluppatori la chiama "application sandbox". Sugli agenti AI: non entrare nei dettagli di un prodotto, il punto è che un programma, anche intelligente, deve avere solo i permessi che gli servono. Domanda: dareste a un'app di torcia il permesso di leggere i contatti?
