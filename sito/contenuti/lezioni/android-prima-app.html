Al computer · 15 minuti

Crea il progetto QuizTPSI

  1. New Project. Scegli il modello con le View, di solito chiamato Empty Views Activity, non "Empty Activity".
  2. Name QuizTPSI, package it.novaula.quiztpsi.
  3. Language Kotlin, Minimum SDK API 24, build in Kotlin DSL.
  4. Premi Finish e attendi la fine della sincronizzazione di Gradle.
  5. Apri MainActivity.kt e activity_main.xml.
Controllo: in MainActivity c'è setContentView(R.layout.activity_main). Se vedi setContent { … } e la parola @Composable, hai scelto il modello Compose: ricrea il progetto.
Il modello predefinito di Android Studio per un nuovo progetto (Empty Activity) usa Jetpack Compose. Il libro e questa unità usano le View con layout XML: serve il modello con "Views" nel nome; nelle versioni recenti si chiama Empty Views Activity, il nome esatto può cambiare. API 24 (Android 7.0) copre quasi tutti i telefoni in uso; Android Studio mostra la percentuale stimata di dispositivi compatibili. La prima sincronizzazione può durare diversi minuti. Se Gradle fallisce per la rete, controllare proxy e siti consentiti.

Mettiti alla prova

In MainActivity vedi setContent { Greeting("Android") } e non c'è nessun activity_main.xml. Che cosa è successo?

  1. Gradle non ha finito la sincronizzazione
  2. Manca l'SDK di Android
  3. Hai scelto Java invece di Kotlin
  4. Hai scelto il modello Compose

Con Jetpack Compose l'interfaccia si scrive in funzioni Kotlin con @Composable, quindi non ci sono layout XML. Per seguire il libro serve il modello con le View.

La A è plausibile perché durante la sincronizzazione mancano davvero dei pezzi, ma i file del modello ci sono subito. Rassicurare: chi ha sbagliato modello non ha perso niente, basta creare un nuovo progetto. Compose non è sbagliato, anzi è il futuro: semplicemente oggi studiamo le View, che si trovano ancora in moltissime app esistenti.

Codice e risorse separati

Il Kotlin dice cosa fare, l'XML in res/ dice come appare. Ogni risorsa ha un id nella classe generata R.

Sul disco i file stanno in app/src/main/: la vista "Android" li raggruppa per tipo.
La cartella del codice compare come "java" nelle versioni meno recenti e come "kotlin+java" nelle più recenti. R.layout.activity_main, R.string.app_name, R.drawable.logo: la classe R viene generata dal build a partire dalle risorse. Il file libs.versions.toml (version catalog) raccoglie le versioni delle librerie. Far aprire a ognuno i file evidenziati e trovare app_name in strings.xml.

Il codice generato

MainActivity, riga per riga

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContentView(R.layout.activity_main)
        ViewCompat.setOnApplyWindowInsetsListener(
            findViewById(R.id.main)) { v, insets ->
            val bars = insets.getInsets(
                WindowInsetsCompat.Type.systemBars())
            v.setPadding(bars.left, bars.top,
                bars.right, bars.bottom)
            insets
        }
    }
}
  • : AppCompatActivity() è l'extends di Java.
  • onCreate è il primo callback del ciclo di vita.
  • Bundle?: lo stato salvato, null al primo avvio.
  • setContentView carica il layout XML.
  • Il resto disegna l'app sotto le barre di sistema: lascialo, e non togliere l'id main.
Il codice generato può variare leggermente con la versione di Android Studio. enableEdgeToEdge e il listener degli insets ci sono perché le app che puntano ad Android 15 (API 35) vengono disegnate da bordo a bordo: senza padding il contenuto finirebbe sotto la barra di stato. Il listener cerca la View con id main nel layout: se nella lezione 5 cambiate il contenitore principale, l'id va mantenuto, altrimenti il progetto non compila. Ripasso Kotlin: override obbligatorio, lambda finale { v, insets -> ... } con due parametri, l'ultima espressione (insets) è il valore restituito.

Dove gira l'app

Emulatore o telefono vero?

Emulatore (AVD)

Un telefono virtuale creato in Device Manager. Comodo, ma vuole un PC potente e la virtualizzazione attiva nel BIOS.

Telefono via USB

Impostazioni, Info sul telefono: tocca 7 volte Numero build. Poi in Opzioni sviluppatore attiva il Debug USB.

Debug wireless

Da Android 11 si collega il telefono via Wi-Fi con un codice di abbinamento, sulla stessa rete del PC.

Al primo collegamento il telefono chiede di autorizzare il computer mostrando la sua impronta RSA: accetta solo sui PC di cui ti fidi.
Il percorso per Numero build varia: su alcuni telefoni sta in Info sul telefono, Informazioni software. Su Windows alcuni telefoni richiedono il driver USB del produttore; per i Pixel c'è il Google USB Driver nell'SDK Manager. Il debug USB dà al PC un controllo ampio sul telefono (installare app, leggere log): dopo il laboratorio conviene disattivarlo. Se la rete della scuola isola i dispositivi tra loro, il debug wireless non funziona: usare il cavo. Chi non ha un telefono Android lavora in coppia o sull'emulatore di un PC potente.

Al computer · 20 minuti

Esegui QuizTPSI

  1. Con l'emulatore: apri Device Manager, crea un dispositivo (per esempio un Pixel) con un'immagine di sistema recente.
  2. Con il telefono: collegalo via USB e accetta l'autorizzazione del PC.
  3. Scegli il dispositivo nella barra in alto e premi Run (il triangolo verde).
  4. In strings.xml cambia app_name in QuizTPSI 5G ed esegui di nuovo.
Controllo: sul dispositivo si apre l'app con il testo Hello World! al centro, e nel menu delle app l'icona si chiama QuizTPSI 5G.
Errori frequenti: virtualizzazione disattivata (l'emulatore non parte: attivare Intel VT-x o AMD-V nel BIOS, e su Windows la piattaforma Hypervisor); spazio disco esaurito (ogni immagine di sistema occupa alcuni GB); telefono non visto (cavo solo di ricarica, driver mancante, debug USB spento). La prima build è lenta, le successive molto meno. Se nessuna postazione riesce, il docente esegue sulla LIM e gli studenti fanno il punto 4 sul proprio progetto, verificando con l'anteprima del layout.

Il manifest

Chi parte per primo lo decide un filtro

<application
    android:icon="@mipmap/ic_launcher"
    android:label="@string/app_name"
    android:theme="@style/Theme.QuizTPSI">
    <activity
        android:name=".MainActivity"
        android:exported="true">
        <intent-filter>
            <action android:name="android.intent.action.MAIN"/>
            <category android:name="android.intent.category.LAUNCHER"/>
        </intent-filter>
    </activity>
</application>
  • MAIN + LAUNCHER: questa Activity è il punto d'ingresso e ha l'icona nel menu.
  • exported="true": il launcher, un'altra app, può avviarla.
  • Da Android 12 exported va scritto per ogni componente con un intent-filter.
Ogni Activity dell'app deve comparire nel manifest (lezione 7). Il nome .MainActivity è relativo al namespace del progetto. Il tema arriva da res/values/themes.xml. android:exported esplicito è obbligatorio per le app che puntano ad Android 12 (API 31) o successivi quando il componente ha un intent-filter.

Quiz a trabocchetto

Togli l'intent-filter MAIN/LAUNCHER dalla MainActivity. Che cosa succede?

  1. Il progetto non compila più
  2. L'app si installa, ma non ha più l'icona nel menu delle app
  3. All'avvio si vede una schermata bianca
  4. Android sceglie da solo un'altra Activity come avvio

Il filtro è solo una dichiarazione per il launcher: senza, il codice compila e l'app si installa, ma nessuna Activity risulta "avviabile". Android Studio infatti segnala che non trova l'Activity predefinita.

Molti pensano alla A: il manifest non è codice compilato in senso stretto, è una descrizione. Le app senza icona esistono davvero: per esempio servizi o tastiere che si aprono dalle Impostazioni. Rimettere subito il filtro, o la Run configuration non saprà che cosa avviare.

Al computer · 20 minuti

Il ciclo di vita dal vivo in Logcat

private val TAG = "QuizTPSI"

override fun onStart() {
    super.onStart()
    Log.d(TAG, "onStart")
}
// uguale per onResume, onPause,
// onStop, onDestroy, onRestart

In onCreate, dopo super, aggiungi Log.d(TAG, "onCreate").

  1. Scrivi i 7 callback con Log.d (importa android.util.Log).
  2. Esegui, apri Logcat e filtra con tag:QuizTPSI.
  3. Ruota il dispositivo, poi premi Home e torna nell'app.
Controllo: la rotazione stampa onPause, onStop, onDestroy, onCreate, onStart, onResume. Home stampa onPause, onStop; il ritorno onRestart, onStart, onResume.
È la tabella della lezione 2, ora vera. Nell'emulatore la rotazione si fa con i pulsanti della barra laterale; sul telefono va attivata la rotazione automatica. Se la rotazione non ricrea l'Activity, controllare che nel manifest non ci sia android:configChanges. Ctrl+O in Android Studio apre la lista dei metodi da sovrascrivere e genera il codice. Il filtro tag: è la sintassi del Logcat delle versioni recenti; nelle vecchie versioni si scrive il tag nella casella di ricerca. Il punto con onDestroy: si vede anche premendo Indietro, ma dalle versioni recenti di Android non sempre per l'Activity principale.

Gradle

Tre numeri da non confondere

android {
    namespace = "it.novaula.quiztpsi"
    compileSdk = 36
    defaultConfig {
        applicationId = "it.novaula.quiztpsi"
        minSdk = 24
        targetSdk = 36
        versionCode = 1
        versionName = "1.0"
    }
}
  • minSdk: la versione più vecchia su cui l'app si installa.
  • targetSdk: la versione per cui l'app è stata provata; ne attiva i comportamenti.
  • compileSdk: le API disponibili quando compili.
  • applicationId: il nome unico dell'app sullo store.
I numeri esatti di compileSdk e targetSdk dipendono dalla versione di Android Studio usata: non importa che coincidano con quelli della slide. versionCode è un intero che deve crescere a ogni pubblicazione; versionName è quello che vede l'utente. Collegamento alla lezione 2: Google Play impone un targetSdk recente. Per creare il pacchetto: menu Build, voce per generare App Bundle o APK (il nome esatto cambia tra versioni).

Puzzle

Premi Run: metti in ordine che cosa succede

  1. Gradle compila il Kotlin e le risorse
  2. D8 crea il file DEX
  3. Gradle impacchetta un APK di debug firmato con una chiave di prova
  4. adb installa l'APK sul dispositivo
  5. Viene avviata l'Activity con MAIN e LAUNCHER
  6. onCreate chiama setContentView e appare il layout
adb (Android Debug Bridge) è lo strumento a riga di comando che parla con il dispositivo; Android Studio lo usa dietro le quinte. La chiave di debug viene creata automaticamente sul PC: un APK di debug non si può pubblicare su Google Play. Collegamento con la lezione 3 (kt → class → dex) e la lezione 2 (firma).

Gemini in Android Studio richiede l'accesso con un account Google e l'accettazione dei termini; nei PC della scuola meglio una dimostrazione del docente. Non mandare all'assistente codice o dati riservati. Collegamento con il deck claude-code: gli agenti di programmazione sono utili quando chi li usa sa leggere e controllare il codice.
